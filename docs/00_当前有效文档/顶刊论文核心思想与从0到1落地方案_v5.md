## 0. 结论先行

PC-CNG 目前已经从“规则负样本生成器 + MLP 排序器”演化到“物理化学约束反事实负样本 + Chemformer-LoRA 排序器”的可运行系统，并积累了多数据集、多随机种子、显著性检验和失败审计。这个工程基础足以支撑一篇严谨的化学信息学论文，但**现有结果还不能证明通用 SOTA，也不足以直接支撑 Nature Chemistry、Nature Machine Intelligence、JACS 等顶级期刊主张**。

当前最大问题不是实验数量不足，而是**论文主张、任务定义、代码实现和证据来源没有完全对齐**：

1. 多个“提升”是在 PC-CNG 自己构造的候选集合上测得，尚不能等价为标准 forward prediction 或标准 retrosynthesis SOTA。
2. 当前生成器主体仍以手工编辑算子为主，Chemformer-LoRA 主要承担反应评分，而不是端到端学习反事实编辑策略。
3. “Chemformer baseline”“AiZynthFinder real routes”“DFT validation”“LLM-as-judge”等表述存在实现口径风险，必须逐项核验。
4. 若候选生成方法不同，直接比较 reranker MRR 会混入候选集难度差异；生成器和打分器的贡献必须解耦。
5. 自定义九维评分、任务自行设定的 GO 阈值和内部 benchmark 不能作为顶刊水平或 SOTA 的证据。

因此，下一阶段不应继续扩张下游任务，而应围绕一个可被严格证伪的核心命题重构论文：

> **在固定、外部、无泄漏的反应候选集合上，物理化学约束的反事实负样本是否比随机、检索、模板扰动和无约束生成负样本提供更有效的训练信号，并在真实 HTE、跨反应族和标准候选排序任务上改善模型的可行性判别与校准？**

论文应从“我们做了很多模块”转向“我们识别并解决了反应学习中的一个基础测量问题：什么样的负样本真正刻画反应可行性边界”。

## 1. 项目背景与真正科学问题

### 1.1 领域痛点

公开反应语料主要记录成功反应，失败、低产率、副产物和条件不匹配实验严重缺失。由此产生三个问题：

- 模型主要学习“已发表成功反应分布”，很少直接学习失败边界；
- 随机错误产物过于简单，模型可以依赖明显伪影完成分类；
- 未报道反应不等于失败反应，粗暴生成负样本会制造假阴性。

高价值负样本必须同时满足：

- 与原反应共享足够多的上下文；
- 化学结构合法；
- 反应层面存在明确反事实差异；
- 不与已知成功反应重复；
- 对下游模型具有信息量；
- 假阴性风险被量化，而非被隐藏。

### 1.2 本项目应回答的核心科学问题

不是：

> 能否生成大量“看起来像负样本”的反应？

而是：

> **能否在不把未知反应武断标记为失败的前提下，构造靠近经验可行性边界的反事实候选，使模型在真实失败/低产率数据、跨域数据和固定候选排序任务上获得可复现收益？**

### 1.3 论文核心对象的重新定义

PC-CNG 生成的样本统一称为：

`synthetic counterfactual reaction candidates`

除非有真实实验或可靠数据库证据，否则不得直接称为：

- failed reactions
- infeasible reactions
- true negatives
- experimentally invalid reactions

训练标签采用三值或软标签：

- `positive`：有实验或数据库支持的成功反应；
- `negative_observed`：有实验支持的失败、零转化或低于预定义产率阈值；
- `counterfactual_unknown`：模型生成且未被实验确认的反事实候选。

对于 `counterfactual_unknown`，使用风险加权排序损失或 PU/partial-label 学习，不得默认赋予绝对负标签。

## 2. 当前仓库真实能力审计

### 2.1 已形成的工程资产

当前仓库已具备：

- 规则驱动的反应中心局部编辑与候选过滤；
- atom mapping、反应中心抽取、RDKit 合法性检查；
- Morgan/GraphStats/GNN/Transformer 类评分组件；
- Chemformer 风格预训练权重加载与 LoRA 适配代码；
- same-context candidate reranking；
- low-yield 分类、条件预测、迁移评估、多任务实验；
- 10-seed 评估、配对显著性、结果 manifest 和大量单元测试；
- USPTO/OpenMolecules、HiTEA、RegioSQM20、ORD、Ni coupling 补充数据的处理资产。

这些资产证明项目已经过了 MVP 阶段。

### 2.2 当前可安全主张

在重新复核原始 artifact 后，可以保留以下类型的主张：

1. PC-CNG 可生成满足预定义结构约束的反事实候选；
2. 在若干内部 same-context candidate sets 上，PC-CNG 增强训练优于部分随机或启发式基线；
3. 预训练 Transformer + LoRA 比仓库早期浅层模型更强；
4. 若干跨数据集 head fine-tuning 实验显示正向迁移；
5. 项目具备较强工程可复现性和失败结果披露意识。

### 2.3 当前不得直接主张

在 P4 审计完成前，不得写入摘要或标题：

- “achieves SOTA reaction prediction”；
- “outperforms Chemformer”而不说明 Chemformer 是零样本打分器还是标准微调模型；
- “AiZynthFinder route-ranking SOTA”而未使用其正式 policy/filter 模型及公共协议；
- “DFT confirms infeasibility”而计算量级、能量定义和单位尚未完全核验；
- “LLM expert panel”而实际执行的是规则 fallback、离线代理或未经确认的模型；
- “distribution preserving”仅因为 KS 检验未拒绝；
- “all five failures were reversed”作为科学贡献；
- 用自定义九维分数证明达到某期刊标准。

## 3. 科研故事重构

### 3.1 推荐故事主线

**第一幕：数据偏差。**  
反应模型从成功文献中学习，但现实实验包含大量失败和竞争路径。随机负样本无法模拟这些边界案例。

**第二幕：核心矛盾。**  
越困难的负样本越有训练价值，但也越可能是假阴性。领域缺少同时衡量化学合理性、困难度与假阴性风险的统一框架。

**第三幕：PC-CNG 切口。**  
从已知成功反应出发，通过反应中心感知的受约束反事实编辑产生候选，并把候选作为“未知反事实”而非绝对失败；再通过多源证据估计其风险和训练权重。

**第四幕：关键验证。**  
在固定外部候选集合和真实 HTE 数据上，比较不同负样本策略对同一 backbone 的影响，严格解耦候选生成和模型评分。

**第五幕：科学 insight。**  
回答哪些负样本真正有效：

- 距离正样本多近最有价值；
- 哪些编辑类型提升最大；
- 何时 hard negative 变成高风险假阴性；
- 真实负样本数量与合成反事实收益之间是什么关系；
- 不同反应族的失败边界是否共享。

### 3.2 一句话主张

> PC-CNG 将负反应学习重新表述为带不确定性的反事实边界学习：它在反应中心和物理化学约束下构造未知反事实候选，并通过固定候选、真实 HTE 与跨域评估证明，经过风险控制的边界候选比常见随机或启发式负样本提供更有效、更可校准的训练信号。

### 3.3 推荐标题

首选：

**Learning Reaction Feasibility Boundaries with Risk-Aware Counterfactual Negatives**

备选：

- **Physicochemically Constrained Counterfactual Negatives for Reaction Feasibility Learning**
- **Beyond Random Negatives: Counterfactual Boundary Learning for Chemical Reactions**

不建议在标题中直接写：

- SOTA
- failed reaction generation
- top-journal
- universal reaction model

## 4. 科学假设与可证伪设计

### H1：局部反事实负样本优于随机负样本

在同一 backbone、同一正样本、同一候选数量和同一训练预算下，PC-CNG 候选应优于：

- random product mismatch；
- random atom corruption；
- Tanimoto retrieval negatives；
- template perturbation；
- unconstrained graph edits。

主要验收指标不是训练集分类准确率，而是：

- 真实 HTE 失败/低产率识别 AUPRC；
- 固定外部候选排序 MRR/NDCG；
- calibration error；
- OOD reaction-family performance。

### H2：约束不是单纯提高合法率，而是提高单位样本信息量

需要比较：

- 无约束编辑；
- 仅结构合法约束；
- 反应中心约束；
- 结构 + 反应中心 + 数据库去重 + 风险权重。

若约束只提高 RDKit validity，但不改善真实任务，则 C1 不能作为核心贡献。

### H3：负样本价值呈非单调困难度曲线

将候选按正样本相似度、模型 margin、ensemble uncertainty 分箱，检验下游收益是否呈倒 U 型：

- easy negatives：信息量不足；
- boundary negatives：收益最大；
- ultra-hard negatives：假阴性率和训练不稳定性上升。

不再预设固定 `[0.10, 0.35]` 等人为区间；区间由开发集上的风险—收益曲线确定，并在测试集冻结。

### H4：少量真实负样本可以校准，但不是凭空定义失败类型

使用真实 HTE/低产率数据学习风险校准头或原型，不要求人工设定十种失败类型均有可靠标签。优先采用：

- observed yield bins；
- no-product / low-conversion；
- regioisomer competition；
- condition-specific failure；
- side-product observed。

对没有真实标签的“failure type”只作为解释性 latent cluster，不报告分类 accuracy。

### H5：收益必须跨生成器、跨 scorer 或跨数据源成立

至少满足二者之一：

- 用 PC-CNG 候选训练 A 模型，在外部 B 模型或公开基准上获益；
- 在一个数据集校准生成器，在另一个真实数据集测试获益。

只有在自建候选 + 自建 scorer 上获益，不足以支撑论文主结论。

## 5. 数据集路线

### 5.1 必选数据

#### A. 大规模成功反应语料

- USPTO/OpenMolecules：预训练与候选来源；
- ORD：结构化条件与补充外部数据。

用途：

- 学习反应语法；
- 建立数据库去重索引；
- 训练基础 scorer；
- 构造 family/scaffold/template split。

#### B. 真实 HTE/失败或低产率数据

优先级：

1. HTEa 中具有可解释标签和同一条件网格的子集；
2. Doyle/Merck 类 C–N、Suzuki、metallaphotoredox HTE 公共数据；
3. RegioSQM20 的区域选择性候选；
4. Ni coupling 文献数据作为特定反应族补充；
5. ORD 中带产率和条件的高质量子集。

要求每个数据集建立：

- 原始来源与许可；
- 标签定义；
- 单位统一；
- 反应角色分配；
- 同一实验网格的 group ID；
- 缺失值模式；
- leakage audit；
- 可复现下载或构建脚本。

### 5.2 当前数据覆盖的主要盲区

- 真实零转化和失败标签仍不足；
- HTEa 是否真的是统一来源的高通量实验集合需要逐子集审计；
- ORD 规模小且条件类别长尾；
- USPTO 的低产率和缺失产率存在报告偏差；
- Ni coupling 数据不能代表广泛反应空间；
- 商业数据库不能作为公开论文的唯一证据。

### 5.3 切分协议

至少报告：

1. `random split`：仅作兼容性结果；
2. `product scaffold split`；
3. `reaction template split`；
4. `reaction family held-out`；
5. `time split`：按公开日期或专利年份；
6. `lab/publication/HTE plate split`：如元数据允许。

必须进行双向污染检查：

- 正样本跨 split 重复；
- 候选产物跨 split 重复；
- 模板重叠；
- parent reaction 泄漏；
- 预训练语料与测试集重叠；
- fingerprint nearest-neighbour 泄漏。

## 6. 模型架构重新设计

### 6.1 总体原则

当前“规则生成器 + 强 scorer”可以作为可靠基线，但不应伪装成端到端学习生成器。推荐采用双层架构：

1. **Counterfactual Proposal Model**：提出结构化编辑；
2. **Risk-Aware Reaction Scorer**：预测相对可行性、未知风险和训练权重。

### 6.2 Proposal Model

输入：

- atom-mapped reactants/products；
- reaction center；
- reagents/conditions；
- reaction-family embedding。

输出分解为：

- edit locus；
- edit operator；
- affected atoms/bonds；
- optional condition edit；
- stop action。

优先实现结构化图编辑，而非自由生成完整 SMILES。候选操作包括：

- regioisomeric bond migration；
- chemoselective competing center；
- leaving-group or nucleophile substitution；
- bond-order alternative；
- missing/alternative activation；
- observed-like side-product edit。

推荐架构：

- reaction graph encoder：Graph Transformer 或 edge-aware MPNN；
- condition encoder：Transformer/set encoder；
- edit decoder：factorized pointer heads；
- validity mask：在 action logits 前屏蔽非法编辑；
- uncertainty head：预测候选是否超出训练支持域。

规则编辑器保留为：

- proposal prior；
- teacher；
- fallback；
- 关键 baseline。

### 6.3 Risk-Aware Reaction Scorer

共享预训练反应 backbone，至少包含三头：

- `s_feasibility`：相对可行性分数；
- `s_observed_negative`：真实失败/低产率概率；
- `u_epistemic`：模型不确定性或 OOD 风险。

训练目标：

```text
L = L_pairwise_observed
  + λ1 L_positive_unlabeled
  + λ2 L_calibration
  + λ3 L_consistency
  + λ4 L_edit_type_aux
```

对合成候选使用样本权重：

```text
w_i = validity_i × support_i × boundary_value_i × (1 - false_negative_risk_i)
```

### 6.4 生成器训练

训练顺序：

1. 通过成功反应的真实 graph edits 预训练 edit reconstruction；
2. 用真实竞争产物/区域异构体监督可替代编辑；
3. 用规则编辑器产生 proposal，进行 imitation learning；
4. 用真实 HTE 下游收益做 reranking 或 preference fine-tuning；
5. 最后才考虑 RL，不以 PPO 作为起点。

### 6.5 是否需要多任务学习

当前仓库已有证据表明简单共享 backbone 的多任务学习未稳定优于单任务。下一阶段不再把多任务作为主贡献。只有在任务间梯度冲突分析、PCGrad/GradNorm 或 task-specific adapter 明显改善后，才作为附加结果。

## 7. 下游任务取舍

### 7.1 核心任务一：真实 HTE 可行性/产率边界学习

任务：

- 给定同一实验网格中的反应组合，识别成功、低产率和失败；
- 或预测 yield，并重点评估低产率尾部。

指标：

- AUPRC（失败/低产率为正类）；
- ROC-AUC；
- balanced accuracy；
- MAE/RMSE；
- top-decile enrichment；
- ECE/Brier；
- reaction-family macro average。

这是最能证明负样本科学价值的核心任务。

### 7.2 核心任务二：固定外部候选排序

由独立方法生成候选，并冻结候选集合。所有 scorer 在完全相同候选上评估。

候选来源至少包括：

- 公共 retrosynthesis/forward 模型 beam；
- template system；
- retrieval system；
- PC-CNG；
- 混合 union 候选。

报告：

- candidate coverage；
- oracle top-k；
- MRR/NDCG/Top-k；
- 按候选来源分层结果；
- 固定候选和动态候选两套协议。

### 7.3 核心任务三：低数据与跨域迁移

设置：

- 20/50/100/500 observed negatives；
- source→target reaction family；
- source HTE dataset→target HTE dataset；
- zero-shot、linear probe、head fine-tune、full fine-tune。

避免使用随机产品作为唯一测试负样本。

### 7.4 次要任务

可作为补充：

- condition prediction；
- reaction class prediction；
- yield regression；
- multi-task learning；
- internal same-context reranking。

不得让次要任务冲淡主线。

## 8. 测评协议

### 8.1 三层评估

#### 层 1：候选质量

- RDKit validity；
- atom/charge balance；
- edit locality；
- duplicate rate；
- descriptor shift；
- reaction-family coverage；
- edit-type diversity。

descriptor distribution 必须报告 effect size、Wasserstein distance/MMD 和置信区间，不能用“KS p > 0.05”证明相同。

#### 层 2：假阴性风险

- 数据库精确/子结构/模板检索；
- 多个独立 scorer；
- nearest-neighbour evidence；
- uncertainty；
- 专家或真实 LLM 审查；
- 小规模真实实验或可靠计算化学。

输出不是简单 pass/fail，而是风险等级：

- low risk；
- ambiguous；
- likely feasible；
- known positive collision。

#### 层 3：下游效用

固定 backbone、训练预算和候选数量，比较不同 negative source。

必须同时报告：

- 绝对性能；
- 对 positive-only 的增量；
- 对 random/Tanimoto/template 的增量；
- 置信区间；
- effect size；
- 训练稳定性；
- 计算成本。

### 8.2 统计方法

10 seeds 可以保留，但不应只对 seed 均值做 t-test。推荐：

- 以 reaction group/family 为 cluster 的 paired bootstrap；
- seed × group 两级 bootstrap；
- permutation test；
- 多重比较校正；
- 报告每个数据集的 effect size，而非只报告 pooled p-value。

### 8.3 必做消融

- 无物理化学约束；
- 无反应中心约束；
- 无数据库去重；
- 无风险权重；
- 规则 proposal vs learned proposal；
- Chemformer/Graph Transformer/GNN scorer；
- random/Tanimoto/template/unconstrained baselines；
- 同数量候选；
- 同困难度匹配候选；
- observed negatives 数量曲线；
- edit operator 单独贡献；
- generator/scorer 交叉矩阵。

最关键的是 **generator × scorer cross-evaluation matrix**，例如：

| Training negatives | MLP scorer | GNN scorer | Transformer scorer | External scorer |
|---|---:|---:|---:|---:|
| Random |  |  |  |  |
| Tanimoto |  |  |  |  |
| Template |  |  |  |  |
| Rule PC-CNG |  |  |  |  |
| Learned PC-CNG |  |  |  |  |

这能证明收益来自负样本，而不是特定 scorer。

### 9.1 当前客观定位

若立即投稿，最合理目标是：

- Chemical Science；
- Digital Discovery；
- JCIM；
- Patterns（取决于故事与 benchmark 完整性）。

当前不建议直接以 Nature Chemistry、Nature Machine Intelligence、JACS 为主投，原因是：

- 缺少无争议的公共 SOTA 对比；
- 缺少真实 wet-lab validation；
- 生成器的学习机制仍不够核心；
- 关键结果依赖内部候选定义；
- 若 LLM/DFT 实现口径不准确，可信度风险很高。

### 9.2 冲击更高层级所需门槛

至少满足以下四项：

1. 在真实 HTE 外部测试上显著优于所有负样本基线；
2. 在固定公共候选集合上至少与强公开模型持平，并有明确互补收益；
3. learned proposal model 相比规则 proposal 带来可解释的增益；
4. 有真实化学家双盲审查或小规模实验验证。

### 9.3 顶刊故事的最低证据链

```text
真实 reporting bias
→ 随机负样本不能刻画边界
→ PC-CNG 构造风险可控的反事实候选
→ 在固定候选和真实 HTE 上带来独立收益
→ 倒 U 型困难度规律和假阴性风险被量化
→ learned proposal / observed negatives 校准解释该规律
→ 专家或实验验证支持
```

## 10. 当前最大的盲区

### 10.1 任务定义盲区

“candidate reranking”可以非常容易，也可以非常困难。必须明确候选由谁生成、gold 是否在候选中、候选重复率和 oracle coverage。没有这些信息，MRR 数字不可比较。

### 10.2 基线盲区

“Chemformer”不等于单一 baseline。需要区分：

- pretrained zero-shot log-likelihood；
- supervised fine-tuned Chemformer；
- Chemformer trained with random negatives；
- Chemformer trained with PC-CNG negatives；
- generative beam ranking；
- encoder-only reaction classifier。

### 10.3 证据真实性盲区

任何以下异常都必须触发自动审计：

- MRR 或 accuracy 接近 1.0；
- 极端能量值；
- 测试性能远超训练常识；
- baseline 低到不合理；
- 仅修改特征即大幅“翻盘”；
- p-value 极小但样本构造复杂。

### 10.4 生成器贡献盲区

强 scorer 可以掩盖弱 generator。必须在统一 scorer 上比较 generator，也必须在统一 generator 上比较 scorer。

### 10.5 化学标签盲区

“未反应”“低产率”“副产物”“区域异构体”“错误条件”不是同一负标签。混合训练可能使模型学到数据源差异而非化学边界。

## 11. 项目成功判据

### 11.1 技术成功

- 证据审计没有发现会推翻主结论的泄漏或伪实现；
- 至少一个真实 HTE 外部测试集上，PC-CNG 比最佳非 PC-CNG negative baseline 提升 AUPRC 或 MRR，95% CI 全正；
- generator × scorer cross-evaluation 中，PC-CNG 在至少 3/4 scorer 上正向；
- 风险加权显著改善 calibration 或降低 known-positive collision；
- learned proposal 在效用—合法率 Pareto 前沿上优于规则 proposal。

### 11.2 科研成功

- 发现可复现的困难度—收益—假阴性三者关系；
- 说明哪些反应族共享失败边界，哪些不共享；
- 证明少量 observed negatives 如何校准 synthetic counterfactual candidates；
- 发布可复用的 fixed-candidate benchmark 和 leakage audit。

### 11.3 顶刊成功

- 公共 benchmark 上有强外部比较；
- 真实 HTE 与固定候选两条证据链均成立；
- 真实化学家或实验验证完成；
- 论文主张不依赖自定义评分和内部阈值；
- 所有关键数字可从原始 artifact 一键重建。
