# P4 Goal：Evidence-First Rebuild（Trae 执行版）

> **日期**：2026-07-21  
> **目标**：把 PC-CNG 从“内部结果丰富但证据口径混杂”的项目，推进为“任务定义固定、实现可核验、主张可复现、具备强刊或顶刊评审防御力”的研究。  
> **原则**：P4-00 未完成前禁止新增 headline claim；P4-01/P4-02 未通过前禁止继续优化模型。

---

## 0. P4 总目标

P4 只回答一个问题：

> 在固定、外部、无泄漏的候选集合和真实 HTE 测试上，PC-CNG 负样本是否提供独立于 backbone 和候选生成器的可复现收益？

阶段完成后必须给出三选一决策：

- **A：顶刊冲刺**：真实 HTE + fixed-candidate + learned proposal + external validation 均通过；
- **B：强刊投稿**：fixed-candidate + HTE 至少一条强证据成立，架构创新有限；
- **C：停止扩张，写 benchmark/negative result paper**：核心收益在严格协议下不成立。

---

## 1. 不可违反的硬约束

1. 不删除或重命名已有 `results/` 目录；
2. 所有 P4 输出使用 `p4_` 命名空间；
3. 每个新模块必须有单元测试；
4. 所有 headline 结果必须基于冻结 split 和冻结 candidate manifest；
5. 所有性能对比必须同候选、同 backbone、同训练预算；
6. 不得将 synthetic counterfactual candidates 写成 experimentally failed reactions；
7. 不得用自定义九维评分决定期刊；
8. 发现数据泄漏或实现不一致时，先修复并重跑，不得解释性绕过；
9. 所有异常值必须生成 audit report；
10. 不得把规则 fallback 写成 LLM、DFT、AiZynthFinder 或公开 SOTA 模型。

## 3. 任务清单

### P4-00：Claim-to-Artifact 证据审计

**优先级**：最高，阻塞全部任务。

**目标**：逐条核验 manuscript v3、核心方案、README 和结果表中的所有数字与方法名。

**必须审计的高风险主张**：

- Chemformer-LoRA 是否加载了真实预训练 checkpoint；
- “Chemformer baseline”究竟是 zero-shot、fine-tuned 还是内部 encoder；
- AiZynthFinder 是否加载正式 policy/filter 模型；
- LLM-as-judge 是否真的调用了三个独立 LLM；
- xTB/DFT 是否真实运行，能量定义和单位是否正确；
- HTEa 来源、标签和 group 构造；
- MRR 接近 1.0 的所有任务；
- Tanimoto-NN 泄漏修复是否充分；
- 10-seed 表格是否来自真实独立训练；
- manuscript 中数据规模、参数量、throughput 和 CI 是否可重建。

**实现步骤**：

1. 新建 `pc_cng/audit/claim_registry.py`；
2. 抽取 manuscript 中所有带数值的 claim；
3. 每条 claim 关联：
   - source artifact；
   - generating command；
   - git commit；
   - input manifest；
   - model checkpoint；
   - exact metric function；
4. 对无法重建的 claim 标为 `UNVERIFIED`；
5. 对实现名称不一致标为 `MISLABELED`；
6. 对异常值执行独立 sanity check；
7. 生成机器可读 registry。

**输出**：

- `docs/00_当前有效文档/P4_claim_audit_20260721.md`
- `results/p4_claim_audit/claim_registry.json`
- `results/p4_claim_audit/recomputed_metrics.csv`
- `results/p4_claim_audit/anomaly_report.md`
- `tests/test_claim_registry.py`

**验收命令**：

```bash
python -m pc_cng.audit.run_claim_audit \
  --manuscript docs/manuscript_v3_20260720.md \
  --repo-root . \
  --output-dir results/p4_claim_audit

pytest chem_negative_sampling/tests/test_claim_registry.py -q
```

**Go/No-Go**：

- GO：所有 headline claims 均为 `VERIFIED` 或被删除/降级；
- NO-GO：存在 ≥1 条无法重建但仍保留在摘要/结论的 claim。

### P4-01：冻结任务定义与 Candidate Manifest

**依赖**：P4-00。

**目标**：防止候选集合变化导致方法不可比。

**任务**：

建立三个固定 benchmark：

1. `P4-HTE-Feasibility`；
2. `P4-Fixed-Forward-Candidates`；
3. `P4-Fixed-Retro-Candidates`。

每个 benchmark 必须记录：

- source reaction ID；
- gold candidate；
- candidate generation method；
- candidate rank before scoring；
- canonical SMILES；
- atom mapping；
- duplicate flags；
- train overlap；
- nearest-neighbour similarity；
- reaction family；
- split assignment；
- oracle coverage。

**候选来源**：

- random；
- Tanimoto retrieval；
- template perturbation；
- rule PC-CNG；
- unconstrained edits；
- external beam candidates（可获得时）；
- learned PC-CNG 在 P4-06 后追加，但不得修改原 benchmark。

**输出**：

- `data/p4/manifests/hte_feasibility_v1.json`
- `data/p4/manifests/fixed_forward_candidates_v1.json`
- `data/p4/manifests/fixed_retro_candidates_v1.json`
- `docs/00_当前有效文档/P4_benchmark_contract.md`
- `tests/test_p4_candidate_manifest.py`

**验收**：

- 每组恰好一个 gold；
- gold 不因方法而变化；
- candidate set hash 固定；
- 无跨 split parent reaction 泄漏；
- oracle Top-k 被报告。

**Go/No-Go**：

任何 benchmark 若 gold/候选构造无法被第三方理解，NO-GO。

### P4-02：真实 HTE 数据与 PC-CNG 评估修复

**依赖**：P4-01。

**目标**：解决当前 HTE 评估中 PC-CNG 结果 NaN、标签语义不清和随机负样本代替真实失败的问题。

**任务**：

1. 逐子集审计 HTEa；
2. 明确每行是：
   - measured yield；
   - no product；
   - low conversion；
   - missing；
3. 对同一实验网格建立 group；
4. 修复 PC-CNG 输出 schema；
5. 构建真实任务：
   - binary low-yield；
   - ordinal yield bin；
   - yield regression；
   - within-plate ranking；
6. 比较 positive-only、random、Tanimoto、template、rule PC-CNG。

**主要指标**：

- low-yield AUPRC；
- macro-AUPRC；
- Brier/ECE；
- yield MAE；
- plate-level NDCG；
- reaction-family macro average。

**输出**：

- `data/processed/p4_hte_normalized.parquet`
- `data/p4/manifests/hte_split_v1.json`
- `pc_cng/data/build_p4_hte.py`
- `pc_cng/evaluation/run_p4_hte_eval.py`
- `results/p4_hte_eval/`
- `tests/test_p4_hte_schema.py`
- `tests/test_p4_hte_eval.py`

**验收命令**：

```bash
python -m pc_cng.data.build_p4_hte \
  --output data/processed/p4_hte_normalized.parquet \
  --manifest data/p4/manifests/hte_split_v1.json

python -m pc_cng.evaluation.run_p4_hte_eval \
  --manifest data/p4/manifests/hte_feasibility_v1.json \
  --negative-sources none,random,tanimoto,template,rule_pccng \
  --seeds 20260710,20260711,20260712,20260713,20260714,20260715,20260716,20260717,20260718,20260719 \
  --output-dir results/p4_hte_eval
```

**Go/No-Go**：

- Strong GO：PC-CNG 比最佳其他 negative baseline 的 AUPRC 或 plate-NDCG 提升 ≥2 pp，cluster bootstrap 95% CI 全正；
- Weak GO：提升 >0 且 CI 全正；
- NO-GO：CI 跨 0 或性能下降。

**任务**：

- 所有训练方法使用相同正样本和候选数量；
- 单独报告各候选来源；

**Scorer**：

- Morgan MLP；
- GNN；
- Chemformer zero-shot；
- Chemformer supervised；
- Chemformer-LoRA；
- external model（若合法可运行）。

**输出**：

- `pc_cng/evaluation/run_fixed_candidate_benchmark.py`
- `results/p4_fixed_forward/`

### P4-04：Generator × Scorer 因果矩阵

**依赖**：P4-02、P4-03。

**目标**：证明贡献来自负样本策略，而不是强 backbone。

**矩阵**：

Negative source：

- random；
- Tanimoto；
- template；
- unconstrained edit；
- rule PC-CNG；
- learned PC-CNG（P4-06 后补）。

Scorer：

- MLP；
- GNN；
- Chemformer-LoRA；
- external/frozen scorer。

**控制变量**：

- 相同候选数；
- 相同训练步数；
- 相同正负比；
- 相同 split；
- 相同 seed；
- 相同数据预处理；
- 困难度匹配子实验。

**输出**：

- `results/p4_generator_scorer_matrix/summary.csv`
- `results/p4_generator_scorer_matrix/effect_sizes.csv`
- `results/p4_generator_scorer_matrix/interaction_analysis.md`
- Figure：negative source 主效应、scorer 主效应、interaction。

**统计模型**：

可用 mixed-effects model：

```text
metric ~ negative_source + scorer + negative_source:scorer + (1|seed) + (1|reaction_family)
```

**Go/No-Go**：

- PC-CNG negative source 主效应显著为正；
- 或在 ≥3/4 scorer 上 effect size > 0；
- 若只对 Chemformer-LoRA 有效，主张收窄为 backbone-specific augmentation。

### P4-05：Risk-Aware Counterfactual Learning

**依赖**：P4-02、P4-03。

**目标**：不再把所有合成候选当绝对负样本。

**模块**：

- `positive collision retrieval`；
- `ensemble disagreement`；
- `OOD support score`；
- `observed-negative calibrator`；
- `boundary value estimator`；
- `sample weight composer`。

**标签**：

- positive；
- observed negative；
- counterfactual unknown。

**损失对比**：

1. hard binary labels；
2. label smoothing；
3. PU loss；
4. risk-weighted pairwise loss；
5. risk-weighted InfoNCE。

**输出**：

- `pc_cng/models/risk_aware_scorer.py`
- `pc_cng/training/train_risk_aware.py`
- `results/p4_risk_aware/`
- `tests/test_risk_aware_loss.py`

**主要指标**：

- known-positive collision rate；
- AUPRC；
- ECE/Brier；
- HTE performance；
- false-negative sensitivity curve。

**Go/No-Go**：

风险感知方法必须满足至少一个：

- calibration ECE 降低 ≥20%；
- known-positive collision 训练影响显著下降；
- HTE AUPRC 提升且 CI 全正。

### P4-06：Learned Structured Proposal Model

**依赖**：P4-04、P4-05。

**目标**：将规则 proposal 升级为真正可学习的反应图编辑模型，但不牺牲可信度。

**架构**：

- atom-mapped reaction Graph Transformer；
- reaction-center mask；
- edit-locus pointer；
- edit-type classifier；
- atom/bond argument heads；
- validity action mask；
- uncertainty head。

**训练数据**：

1. 真实 reaction edit reconstruction；
2. RegioSQM/HTE observed alternative outcomes；
3. rule proposal imitation；
4. downstream risk-adjusted preference。

**基线**：

- rule PC-CNG；
- shallow learned decoder；
- unconstrained Transformer；
- retrieval proposal。

**输出**：

- `pc_cng/models/structured_edit_proposal.py`
- `pc_cng/training/train_structured_edit_proposal.py`
- `results/p4_learned_proposal/`
- `tests/test_structured_edit_proposal.py`

**验收指标**：

- exact edit recovery；
- top-k edit recall；
- validity；
- uniqueness；
- edit-type coverage；
- HTE/fixed-candidate downstream effect；
- throughput。

**Go/No-Go**：

learned proposal 必须在下游效用—合法率 Pareto 前沿上优于规则版；只提高多样性但降低效用，不升级为主模型。

### P4-07：真实化学审查与可选实验验证

**依赖**：P4-05、P4-06。

**目标**：建立真正独立的化学合理性证据。

**首选方案**：

- 2–3 名有机/药化研究者；
- 双盲；
- 300 条候选；
- 分层抽样：
  - low risk；
  - ambiguous；
  - likely feasible；
  - 各 edit type；
- 不展示生成方法。

**评审问题**：

- structure validity；
- plausible competing outcome；
- likely observed product；
- likely low-yield/failure under given context；
- confidence；
- reason code。

**LLM 只能作为附加 evaluator**，必须记录真实模型名、版本、prompt、温度和调用日期。规则 fallback 不得称作 LLM。

**可选实验**：

选择 20–50 个高价值候选，在合作实验室做小规模验证；若无 wet lab，则不写实验验证。

**输出**：

- `docs/00_当前有效文档/P4_human_review_protocol.md`
- `results/p4_human_review/`
- `results/p4_llm_review/`（可选）
- `results/p4_wetlab/`（可选）

**Go/No-Go**：

- 人类 κ ≥0.6 且多数 low-risk candidates 被认为是合理竞争路径；
- 若未执行真人审查，不得冲击依赖实验可信度的顶级期刊。

## 5. Trae 执行顺序

Trae 必须严格按以下顺序工作：

```text
P4-00
  ↓
P4-01
  ↓
P4-02 + P4-03
  ↓
P4-04 + P4-05
  ↓
P4-06
  ↓
P4-07
  ↓
P4-08
  ↓
P4-09
```

禁止在 P4-00/P4-01 未完成时直接训练新模型。  
禁止为了“翻盘”修改测试集、候选集合或 GO 阈值。  
任何结果异常时，先执行数据和实现审计，再解释科学原因。
